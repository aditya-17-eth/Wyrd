# Canonical Pune rainfall specification

An exact per-event canonical JSON document is generated by `scripts/prepare-event.mjs`. The onchain EventTerms store its Keccak-256 hash and independent archive URL. The sample standard source is:

```json
{"endpoint":"https://archive-api.open-meteo.com/v1/archive","parameters":{"latitude":"18.5196","longitude":"73.8554","start_date":"<committed IST calendar date>","end_date":"<same date>","daily":"rain_sum","models":"era5","timezone":"Asia/Kolkata","precipitation_unit":"mm","cell_selection":"nearest"},"governingGrid":{"latitude":"18.5","longitude":"73.75"},"validatorVersion":"aegis-era5-daily-v2"}
```

Observation is exactly 00:00–00:00 IST (UTC+05:30), represented as UTC Unix seconds. Trigger YES when the provider's reported daily rain sum is at least 50.000 mm. Parse decimal values exactly into milli-mm and reject incompatible precision rather than round across the threshold. Reject wrong grids, dates, units, timezone/offset, source parameters, missing/null values, duplicates, or malformed responses.

The first Saturday at least 72 hours after seeding supplies the initial live date. Purchase cutoff is one day before observation; quote expiry is at most one day after publication and cannot exceed cutoff or the vault's issuance deadline. Contracts enforce all boundaries independently of the browser clock.

Capture becomes eligible at observationEnd + 5 days. The first complete validated response archived by AEGIS's service before observationEnd + 14 days becomes the governing snapshot. All preceding failed attempts are retained. Selection is locked before its value is returned to the operator. This means first captured by this trusted service, not provably the first response published anywhere on the internet.

Open-Meteo's ERA5 selector can serve preliminary ERA5T and later revisions. The API does not supply an immutable upstream release identifier in this response. The event freezes endpoint, complete query, validator version, returned bytes, capture time, and selection/revision rules; it does not falsely promise a final ECMWF release within 14 days. Later upstream revisions are ignored after capture.

Commit valid evidence onchain strictly before the deadline. A committed result can be finalized later and can never be invalidated. Open requests become eligible for permissionless timeout INVALID at/after the deadline, using the reason “No valid evidence committed by deadline.” Data availability alone is not proven by this timeout; trusted-authority withholding remains possible.

Synthetic fixture specs additionally commit the designated outcome, rainfall value, raw-response hash, and matching manifest hash stored alongside the spec hash. Distinct fixture IDs demonstrate YES/NO/INVALID. Every synthetic surface says TESTNET DEMONSTRATION — SIMULATED EVENT RESULT. Their early-resolution exception cannot be used for live events.

## Versioned source integration

New specifications use the user-configured 18.5196 / 73.8554 query, explicit Asia/Kolkata, millimetres, nearest cell, ERA5, and rain_sum. A read-only provider audit confirmed the expected 18.5 / 73.75 governing grid. Each request sets start_date and end_date to the same committed observationDate. The monthly example URL and timezone=auto are not used for resolution.

Existing v1 specifications retain their original 18.5204 / 73.8567 query and elevation=nan. Their specification, source, evidence, and outcome hashes are not rewritten. The service recognizes both exact allowlisted configurations, with the version committed in the source hash.

Null or unavailable observations, network failures, and HTTP 429/5xx responses are archived as failed attempts without selecting a snapshot or converting missing data into zero rainfall. Eligible transient failures return a suggested retry time; an authorized operator must retry within the committed window. No unattended signer is installed. Wrong dates, units, grids, offsets, nonnumeric rainfall, incomplete arrays, non-JSON responses, and model/endpoint substitutions are rejected.

Before an authorized wallet submits commitEvidence, the UI reloads the archived specification, canonical manifest, and raw bytes; verifies their hashes, calculation, and event binding; checks the first selected live snapshot in the independent catalog; and reads fresh resolver state and chain time. It simulates the unchanged deployed function, estimates gas, requests the authority wallet signature, and waits for a real receipt. Finalization remains a separate permissionless action.

The resolution UI displays verified archived observations (clearly distinguished from onchain commitment), source requests, coordinates, both evidence hashes, retrieval time, and resolution status. Synthetic fixtures remain explicitly labeled replay demonstrations and cannot resolve live markets.
